## 2026-11-13 — R1.1: сеанс crengine и его JNI (Opus)

- **Что сделано.** `ReaderEngine`-сеанс поверх пробы R0: `engines/cre_session.cpp` (`dexp_reader_open/close/page_count/page/set_font/pos/page_of/page_text`), JNI — `engines/reader_jni.cpp` → `ru.ogrpfsense.dexpm8.reader.Engine`. Вид (`LVDocView`) живёт между вызовами, страница рисуется в буфер вызывающего (8 бит, stride = w), к фронту отдаётся ALPHA_8 (16 уровней G0…G15, инверсия — хелпер `engines/cre_gray.h`). Общий код с пробой вынесен: `cre_fonts.h` (шрифты `/system/fonts`). Оба файла — в ту же `.so` `libdexp_cre.so` (3 230 088 б после strip, было 3 219 624). Каталог кэша разметки (`cacheDir/cre`, 24 МБ) задаёт Kotlin из `EinkActivity.onCreate`; `-keep` для `Engine` — в `proguard-rules.pro`.
- **Позиция — xpointer, а не номер страницы.** `pos(page)` — `getPageBookmark`, `pageOf(pos)` — `createXPointer` + `getBookmarkPage`. Проверено: позиция середины FB2 после смены кегля 44 → 56 (373 → 1142 стр.) **попадает в ту же фразу** («XXVII Последнее дело, задержавшее Нехлюдова…»), номер страницы 186 → 693 — это норма, кегль меняет вёрстку. Восстановление из прошлой сессии — `gotoPos(pos)` (xpointer → `goToBookmark` → `getCurPage`): FB2 стр. 186 → 186, EPUB 86 → 86, та же фраза; так и делать в R1.4. `goToPage(n)` для этого не годится: сразу после загрузки из кэша вид ещё не разложен и стр. остаётся 0.
- **Грабли 1 — xpointer создавать ПОСЛЕ перевёрстки.** Первая версия искала `createXPointer(keepPos)` до `setFontSize` и держала объект через перевёрстку: место чтения уезжало с 50 % на 61 %. Строку надо применять к новому DOM: `setFontSize` → `checkRender` → `createXPointer` → `goToBookmark` → `checkRender`.
- **Грабли 2 — `NewStringUTF` и текст книги.** На EPUB процесс падал с `JNI DETECTED ERROR: input is not valid Modified UTF-8: illegal continuation byte 0` (SIGABRT в `dexp-engine`). Причина: обрезка текста по лимиту байт рвала символ UTF-8 посреди кода, а `NewStringUTF` ждёт *Modified* UTF-8. Исправлено: обрезка отступает назад по байтам-продолжениям (`10xxxxxx`) и текст уходит в `jstring` через UTF-16 (`utf8ToJString` в `reader_jni.cpp`), с парами суррогатов для символов вне BMP. Тот же путь у `pos()`. И ещё: `LVDocView::LoadDocument(LVStreamRef())` с пустым потоком падает (`stream->GetSize()` без проверки); закрытие документа — `delete g_view`, деструктор освобождает DOM.
- **Грабли 3 — EPUB: смена кегля теряет фразу (открыто в R1.2/R3).** На «Немезиде» (EPUB, 172 стр.) позиция середины до смены кегля — `/body[1]/DocFragment[26]/body[1]/div[12]/text()[1].105`, после `setFont(56)` `createXPointer` находит узел, `goToBookmark` переводит на стр. 391 (из 769), но текст другой: «возразила Инсигна…» вместо «что мы должны с этим смириться…». На FB2 тот же путь даёт ту же фразу. Причина, вероятнее всего, в **offset внутри текстового узла** (`.105`): EPUB разбит на `DocFragment`, и при перевёрстке CREngine переносит границы фрагментов/боксов, поэтому смещение внутри узла перестаёт соответствовать тому же слову. Что делать (R1.2 или R3): сохранять позицию с привязкой к блочному узлу без offset либо брать середину первой строки страницы (`getCurrentPageMiddleParagraph`), а не `getPageBookmark(precise)`. **Замер важно повторить там же:** при смене кегля номер страницы всегда меняется — критерий только «та же фраза».
- **Замеры на книге 2026-11-13** (Debug, 1404×1600, шрифт Noto Serif 8 pt из системы): «Воскресение» FB2 1,7 МБ — открытие 293–334 мс, 373 стр., страница 51–85 мс; «r0-big5.fb2» 5,1 МБ — открытие 5,47 с, 913 стр., страница 37–63 мс; EPUB «Немезида» — открытие 1,2–1,7 с, 172 стр. **PSS 37,2 МБ** (Native 15,4) на 5-МБ книге — в цели ≤ 60 МБ. Кэш разметки пишется (`cache/cre/<файл>.….cr3`, 2,7 МБ) и читается при повторном открытии (`load` 49–114 мс вместо 399), но **страницы всё равно верстаются заново** (повторное открытие 5-МБ книги 4,0 с) — оптимизировать в R1.3, если откроется медленно. Проверка без экрана (до B3, уберётся в R1.3): `adb shell am start -n ru.ogrpfsense.dexpm8/.ui.EinkActivity --es reader '/sdcard/Books/…'` — `EngineSelfTest` прогоняет открытие, три страницы, позицию, смену кегля, повторное открытие и пишет `page-first.png` во внешний каталог приложения (проверено глазами: кириллица, курсив эпиграфа, заголовок главы).
