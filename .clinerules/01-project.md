# Проект DEXP M8 Prudentia — правила для Cline

Оболочка и читалка для книги DEXP M8 Prudentia. Источник правды — этот репозиторий; заметки, переписка и память могут устареть.
**Важнее общих указаний Cline о проактивности:** не начинать работу без «делай» и не пушить без подтверждения.

## Старт каждой задачи

1. Старт — **ровно один** `run_commands` на ответ. Даже если общие указания Cline требуют параллелить независимые вызовы — здесь нельзя: терминал один на чат, второй параллельный вызов теряет вывод («command completion could not be observed», проверено 2026-11-15). Несколько команд — массивом внутри одного вызова.
   Act — `GIT_ASKPASS=$PWD/tools/git-askpass.sh GIT_TERMINAL_PROMPT=0 git pull --ff-only; git status -sb; git config user.name; cat docs/CONTEXT.md; grep -n '^## ' docs/DEVLOG.md | head -3`
   Plan — то же, но `git fetch` вместо `git pull --ff-only` (изменения запрещены).
   Не проходит, есть незакоммиченное или `user.name` не `denisle` — остановись, покажи вывод, сам не сливай.
2. Из `docs/CONTEXT.md` — «СЛЕДУЮЩИЙ ШАГ». `docs/ROADMAP.md` — не целиком: `grep -nE '^(## |[0-9]+\.)' docs/ROADMAP.md` → нужный пункт `sed -n 'A,Bp'` (пункты плана идут как `15.`, `16.`, а не как `##`). `awk` с русским шаблоном в терминале Cline зависает.
3. `docs/DEVLOG.md` — только верхняя запись: её строки взять из `grep -n '^## '` (от первого `## ` до следующего), не `head -2` — там шапка. `docs/archive/` и `third_party/` — в `.clineignore`: нужен файл (по ссылке из CONTEXT/ROADMAP или движок) — закомментировать строку в `.clineignore`, после работы вернуть.
4. Остальное — по теме: макеты и UI — `docs/DESIGN_USAGE.md`, `design/README.md` (числа — `tools/design_flat.py`, JSON целиком — если не хватило поля), `docs/DESIGN.md` — справочно; читалка — `docs/READER_SPEC.md`; сборка/установка/git/токены/ошибки — `docs/BUILD.md`; рендер, структура кода, E-Ink — `docs/ARCHITECTURE.md`; чат дизайна — `docs/DESIGN_QUESTIONS.md`; карта документов — `README.md`.

Ответа нет в CONTEXT — `grep -rn 'слово' docs/*.md` (файлы короткие), затем спросить; не выдумывать.

## Как работаем

- Один шаг за раз. Замечания сначала записывать, делать — после «делай».
- Действие человека (сборка на книге, настройка, проверка на экране) — расписать по шагам, ждать подтверждения после каждого.
- После шага — коммит и push; перед `git push` показать `git diff --stat` и дождаться подтверждения.
- Что куда писать (без дублей): `CONTEXT.md` — только «СЛЕДУЮЩИЙ ШАГ», номер пункта, ссылки, один экран; `ROADMAP.md` — статусы (✅) и открытые замечания (вопросы дизайну — `DESIGN_QUESTIONS.md`); `DEVLOG.md` — что сделано, решения и результаты проверок (запись ≤ ~6 пунктов, не более ~5 записей; в ROADMAP и CONTEXT — одна строка со ссылкой); грабли окружения — сразу в `BUILD.md`; пункт закрыт — его «подробно» и записи DEVLOG сразу в `docs/archive/`.
- Код — строго по `docs/ARCHITECTURE.md` (палитра G0–G15, без прозрачности/анимаций/скролла, дизайн-px; без AndroidX/Material/Compose) — правила там, здесь не дублируются.
- Правка кода → `tools/typecheck.sh`; менялись экраны или снимки — ещё `python3 tools/check_design.py`; менялось нативное — `assembleDebug`. Результат (число классов/проверок) — строкой в DEVLOG.
- Коммит: `<пункт или раздел>: что сделано кратко`, по-русски, без точки в конце (`R2.5б: рамка «Вручную» ставится касанием`, `BUILD: грабля — …`). Один шаг — один коммит.
- Ответы пользователю и комментарии в коде — по-русски.
- Даты — по `date`. Долгие команды (`typecheck.sh`, Gradle) — `> /tmp/x.log 2>&1`, затем читать файл. `JAVA_OPTS` скрипты ставят сами.
- Gradle — `~/.local/gradle-8.7/bin/gradle` (в PATH его нет). Под `denisle`, не root. Токен git — `~/.config/dexp-m8/git-push-token`. git-команды с русским текстом (`log`, `show`, `diff`) — только с `--no-pager`, иначе терминал отдаёт мусор.

## Кто что делает

- **Чат дизайна** (Claude, Penpot): макеты, дизайн-система, снимок `design/v5/*.json`, документы по дизайну и ТЗ. **Cline в VS Code**: код, сборка, проверка на книге.
- Макет в Penpot из Cline не менять; можно читать, снимать ещё не снятый экран (`tools/penpot_dump.js`, `design/README.md`) и проверять `tools/check_design.py`. Trilium — только по прямой просьбе.
