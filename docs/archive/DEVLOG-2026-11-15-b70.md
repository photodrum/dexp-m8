# Журнал разработки — B70 «Шрифт и размер» (2026-11-15)

> Перенесено из `docs/DEVLOG.md` 2026-11-15 после проверки на книге и закрытия пункта.

## 2026-11-15 — B70 проверен на книге, три дефекта исправлены (Opus)

- **Проверено на книге** (`6IVJ8C68AP`, APK собран `assembleDebug`): экран B70 открывается с B39
  (строка «Шрифт и размер» нажимается, подпись живая — «Литерата · 59» → «PT Serif · 59»);
  выбор гарнитуры меняет **текст книги**, а не только образец: Литерата 1805 стр., PT Serif 1502,
  Manrope 1179 при кегле 59; место чтения держится (52 %, страница пересчитана по xpointer).
- **Дефект 1 — «Открыть шрифт…» не работал (`UnsatisfiedLinkError`).** Причина: `libdexp_cre.so`
  грузится только при открытии книги, а B70 открывают из настроек, где книги нет; менеджер шрифтов
  (`fontMan`) создаётся в `prepare()` там же. Исправлено: `Engine.registerFont` сам грузит `.so`
  и зовёт новую `dexp_reader_prepare_fonts` перед регистрацией. Стало: `font +PT Serif …
  code=100` на книге.
- **Дефект 2 — имя семейства из файла.** Сравнение `getFaceList` до/после `RegisterFont` не
  находило новое имя, если семейство уже зарегистрировано (копия PT Serif) → `FAIL`. Заменено
  на чтение name-таблицы самим FreeType (`read_family_name`, платформа 3/кодировка 1, name ID 1
  или 16) — он уже слинкован в `dexp_cre`.
- **Дефект 3 — свой шрифт терялся после перезапуска.** Код гарнитуры `FACE_USER + n` живёт только
  в процессе: после старта `Prefs.textFace = 100` указывал на ничто. Добавлено `Prefs.userFontPath`;
  `FontSizeScreen.onAttachedToWindow` перерегистрирует файл (код снова 100), если файла нет —
  откат на Литерату. Проверено: после `force-stop` и запуска шрифт в списке и отмечен.
- **Правки вида по снимкам:** в листе B4 четыре клавиши гарнитур (301.9 шириной, зазор 26.5,
  «Аа» 66/500, название 30/600 в +140, обрезка по клавише) — при трёх подписи влезали, при
  четырёх «Антиква»/«Гротекс»/«PT Serif» налезали на «Аа»; в B70 «Моно» показывается строкой
  только когда он выбран, иначе список по макету (4 строки шагом 152) — с пятой строкой
  «Открыть шрифт…» налезала на раздел «РАЗМЕР» (проверено снимком).
- **Проверки:** `typecheck.sh` — 0 ошибок, 206 классов; `assembleDebug` — успешно; в `.so` внутри
  APK есть `Java_..._registerFontNative` и `dexp_reader_register_font` (иначе `UnsatisfiedLinkError`).
- **Грабля окружения:** `install -r` не перезапускает процесс — старая `.so` остаётся загруженной,
  JNI нового метода не находит. После установки нужен `am force-stop` (записано в `BUILD.md`).

## 2026-11-15 — B70: «Шрифт и размер», PT Serif четвёртой гарнитурой (Opus)


- **Решение пользователя:** делать B70 по макету, с PT Serif. Сделано: PT Serif (OFL,
  `ofl/ptserif`, начертания 400/700) срезан в `res/font/ptserif_400.ttf` / `ptserif_700.ttf`
  (36,7 и 37,4 КБ), набор символов — как у `literata_400.ttf` (294 из 296; нет только `Ѝ`/`ѝ`,
  допущено явно в `ALLOW_MISSING` в `tools/make_fonts.py`).
- **Натив.** Коды гарнитур: 0 Literata, 1 Manrope, 2 моно, **3 PT Serif**, 100+N — свои шрифты.
  Порядок менять нельзя: он в сохранённых `Prefs.textFace`. `face_name` берёт из таблицы
  `FACE_NAMES`; `set_typography` принимает и `FACE_USER + n`. Новая функция
  `dexp_reader_register_font` (+`dexp_reader_forget_user_fonts`) — регистрация `.ttf`/`.otf`
  из папки `Fonts` в рантайме; имя семейства — сравнением `getFaceList` до и после
  `RegisterFont` (своего API «имя из файла» у crengine нет). `libdexp_cre.so` собран NDK 26.3
  без предупреждений; в APK есть и символ `dexp_reader_register_font`, и строка `PT Serif`.
- **Экран B70** `ui/FontSizeScreen.kt` по числам `design/v5/B70.json`: шапка, образец
  41,250 1321×250 (текст гарнитурой и кеглем выбранного), «ШРИФТ» — панель 41,608 1321×616
  со строками по 152 и `check` у выбранной, «РАЗМЕР» — «−/+» 140×110 и поле 213,1325 979×92.
  Строк шрифта **четыре**: Литерата, PT Serif, Manrope и «Моно» из B4 — иначе выбор из листа
  B4 в B70 не показать (гарнитура одна на книгу). Пятая — «Открыть шрифт…»: лист
  `ui/FontPicker.kt` со списком `.ttf`/`.otf` из папки `Fonts`, регистрация в `Engine.worker`.
- **Отступление от макета:** в поле кегля «20 pt», но движок верстает в дизайн-px 8…72
  (умолчание 32) — показываем кегль движка с подписью «pt»; пересчёт по плотности разошёлся бы
  с B4. Вопрос записан в `docs/DESIGN_QUESTIONS.md`.
- **Дверь** — строка «Шрифт и размер» на B39 (`SetReadScreen`): теперь нажимается
  (`SCR_SET_FONT`) и показывает живую подпись «гарнитура · кегль» вместо «Литерата · 20».
- **Проверки:** `typecheck.sh` — 0 ошибок, 206 классов; `check_design.py` — 331 файл, 0 нарушений;
  `check_icons.py` — 169 иконок, 0 проблем; `assembleDebug` — успешно, APK 5 815 104 б (было
  5 157 572: +73 КБ PT Serif). **На книге не проверено** — нужен снимок экрана B70.

## 2026-11-15 — B70: решение по составу шрифтов (Sonnet)

- **Вопрос пользователю:** B70 в макете перечисляет не «Антиква/Гротекс/Моно» (как B4), а конкретные
  шрифты — Литерата / PT Serif / Manrope — плюс строку «Открыть шрифт…» (TTF/OTF из папки `Fonts`).
  PT Serif в проекте нет: в `res/font/` только Literata (400/500/600) и Manrope (200…800), «Моно» —
  системный `Droid Sans Mono` (`face_name` в `app/src/main/cpp/engines/cre_session.cpp`).
- **Решение пользователя:** делаем как в макете — PT Serif кладём в APK (лицензия OFL), гарнитур
  становится четыре, код 3 в нативе (`face_name` → «PT Serif»).
- **Почему это шаг Opus:** гарнитура в движке — код `face` (0/1/2) → имя семейства в
  `apply_typography`, правка `cre_session.cpp` + JNI + пересборка `libdexp_cre.so` + проверка на книге
  (`docs/BUILD.md`: нативная сборка через Gradle/CMake NDK 26.3). По `.clinerules/02-modes.md` натив
  и `.so` — Opus.
- **Что учесть в B70 (для Opus):** (1) кегль в макете в `pt` («20 pt»), движок считает дизайн-px
  8…72 (`Engine.FONT_SIZE_DEFAULT = 32`) — подпись поля как в макете, значение — кегль движка;
  (2) «Открыть шрифт…» требует регистрации чужого TTF/OTF **после** старта, а `fontMan` регистрируется
  один раз в `prepare` (`cre_fonts.h`) — нужен отдельный вызов натива; (3) B4 и B70 пишут в одни и те же
  `Prefs` (`textFace` и т. д.), но подписи наборов разные — согласовать (вопрос в `DESIGN_QUESTIONS.md`);
  (4) замечание 18 (гарнитура у книг со своим `@font-face`) решается здесь же.
- **Записано в документы:** `docs/CONTEXT.md` (СЛЕДУЮЩИЙ ШАГ), `docs/ROADMAP.md` п. 16,
  `docs/DESIGN_QUESTIONS.md` (вопрос 2 — PT Serif снят). Выполнено в записи выше (Opus).
