## 2026-11-12 — 9.7: B26 «Загрузка по Wi-Fi» (Opus)

- **Код:** `core/WifiShare.kt` — HTTP на `ServerSocket` (порты 8080…8089, по одному соединению, поток `wifi-share`): `GET /` отдаёт страницу 3721 б (HTML+JS без внешних файлов), файлы идут по одному запросу `POST /put?name=<имя>` с телом = файл (без multipart), приём потоком в `Books/<имя>.part` → переименование → `Scanner.addFile`. Отказы: не книга, нет размера, нет папки Books, нет места (507), обрыв связи; имя чистится от пути и знаков FAT, занятое — «Имя (2).fb2». `ui/WifiUploadScreen.kt` — B26 по числам снимка; `SCR_WIFI = 19`; кнопки B44 на пустой библиотеке ожили (`EmptyState.libraryHit`), «Сетевые каталоги» пока молчат (п. 10).
- **Проверено на книге (2026-11-12):** сервер поднимается на 8080 (`ip=192.168.100.104`), `curl` получает страницу и шлёт книги: FB2 1,7 МБ и 13,7 МБ приняты целиком, `.exe` отклонён («не книга»), четыре строки в панели, «Готово» с галочкой, дорожка и «10 %» при приёме, «Остановить» → «Запустить» (сокет закрыт, порт не отвечает), выход с экрана гасит сервер, `Books` получает файл нужного размера, книга сразу в библиотеке (523). Вход с B44 проверен: «Загрузить по Wi-Fi» → B26, сервер стартует.
- **Правки после проверки:** шаг 2 в одну строку вылезал за панель — две строки (650/695); заголовок карточки «Пока ничего не принято» не влезал в 420 px — «Пусто»; надпись при пустом списке — «ПРИНЯТО · 0»; поле адреса при остановленном сервере — «Сервер остановлен»; `readLine` читает байты как UTF-8 (сырое не-ASCII имя в URL ломало имя файла).
- **Грабли:** `kotlinc` в `tools/build.sh` без `JAVA_OPTS=-Xmx1600m` падает `OutOfMemoryError` на `ShelfScreen.kt` (как в `BUILD.md` для `typecheck.sh`); `Scanner.fileFormat`/`addFile` — методы экземпляра, не спутника; второй `companion object` в классе Kotlin запрещён (флаг отладки B44 пришлось вынести в отдельный объект, потом убрать); `adb screencap` отдаёт чёрный кадр при погашенном экране — перед снимком `input keyevent KEYCODE_WAKEUP`.
- **Не проверено:** приём при выключенном экране книги (спит — соединение ждёт до `soTimeout` 60 с); два файла одновременно (браузер шлёт параллельно — второй ждёт в `accept`, страница показывает «Отправка…»); поведение при занятом 8080 другим приложением (берётся 8081…8089 — код есть, на книге не проверялось).

## 2026-11-12 — 9.6: решения по B25 до кода (Sonnet)

- **Вопросы закрыты пользователем:** вход в «Файлы» — плитка в разделе B6 «Приложения»; сортировка — переключение «по имени ↔ по дате» без листа; пустая папка — карточка «В папке нет книг»; PDF/CBZ в библиотеке **не показывать**, в «Файлах» показывать; крошки — сегменты кликабельны.
- **Плитка «Файлы» — синтетическая.** B6 строится из `PackageManager`, своего файлового менеджера в системе может не быть (тогда плитки не было бы вовсе). `AppEntry("Файлы", "", "", "files@98.7x102.8")` по алфавиту; «…» не рисуется; в «N установлено» не входит, скрыть и закрепить нельзя.
- **PDF/CBZ из библиотеки** — из `Scanner.EXTS` убрать, база **v5** удаляет строки `pdf`/`cbz` и их `shelf_books`: файлы на диске остаются и сканером не убираются, значит база сама. Строки форматов в B22-фильтре не меняются (их и не было).
- **Числа B25 сняты с `design/v5/B25.json`** и записаны в ROADMAP («9.6 — решения до кода»): шапка, крошки, панель, строки папок и файлов, пагинация. Отступление: шаг строк **172 от 426** (в макете 426…1467, разброс ±7 px), 7 строк на страницу.
- **Новое в API:** `Scanner.addFile(File)` для кнопки «+» (тот же разбор `info()` + `upsert`, без полного прохода), `Words.files`/`Words.folders`, `SCR_FILES = 18`.
- **Вопросы дизайну — в `DESIGN_QUESTIONS.md`:** вид клавиши сортировки без листа и пометка «не поддерживается» у PDF/CBZ в B25 (в макете ни того, ни другого нет).
- **Проверено:** репозиторий чистый, `main` = `origin/main` (`9b8ec78`); код 9.6 не начат — шаг продолжаем с `Scanner.addFile` и `FilesScreen.kt`.
