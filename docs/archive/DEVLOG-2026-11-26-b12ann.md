# 2026-11-26 — п. 27.1–27.2: аннотация FB2 в ядре и JNI (Opus)

## Решения человека (2026-11-26)

- Карточка «Аннотация» на B12 — только у книг, где аннотация есть; без неё экран как раньше.
- Текста — ровно столько, сколько влезает в блок макета (95.1,1331 1213.9×320), хвост — «…» по слову.
- «Читать полностью» открывает книгу, как «Продолжить чтение»: есть позиция — с неё, новая — с начала.
  Отдельного экрана полной аннотации нет.

## Ядро (`app/src/main/cpp/core/book.c`, `book.h`)

- `book_meta.annotation` — `<annotation>` из `<title-info>` (не из `<src-title-info>` и не из
  `<section>` тела: разбор и так кончается на `</title-info>` / `<body>`).
- `meta_field` стал обёрткой над `meta_text(s, n, enc, oom, in_cap, out_cap, paras)`. Для
  аннотации `paras = 1`: границы `<p>`, `<v>`, `<subtitle>`, `<empty-line>` (с префиксом `fb:` тоже)
  ставят метку `\x01` до `buf_normalize`; после схлопывания пробелов `paras_finish` превращает
  метки в `\n` — без пробелов вокруг, подряд — одна, по краям — нет. Байт `\x01` из самого текста
  выбрасывается, чтобы не спутать с меткой.
- Лимиты: `META_ANN_IN` 16 КБ сырых байт (разметка занимает место), `META_ANN_OUT` 4 КБ на выходе
  (на B12 влезает ~400 знаков). Срез по границе символа, `\n` и пробел в хвосте после среза убираются.
- Не закрыта в прочитанном начале файла (64 КБ, огромная аннотация) — `meta_annotation` берёт
  текст до конца буфера, `complete = 0` как раньше.
- Новое для всех полей: `utf8_trim_tail` — если сырой вход срезан посреди многобайтного символа
  (лимит `in_cap` или конец буфера), оборванный хвост убирается до нормализации; раньше такой
  байт уходил в JNI и превращался в U+FFFD.

## JNI и Kotlin

- `jni_bridge.c`: `META_FIELDS` 11 → 12, индекс 11 — аннотация (через `utf8_to_jstring`, не
  `NewStringUTF`: эмодзи и битые байты в чужих FB2).
- `NativeBook.Meta.annotation: String?` = `f.getOrNull(11)`. Сканер и база пока поле не используют
  (27.3, Sonnet).

## 27.3–27.6 (Sonnet): база, сканер, экран, проверка на книге

- `LibraryDb` v14 (`onCreate` — колонка в `CREATE TABLE`, `onUpgrade` — `ALTER TABLE` + `UPDATE books SET mtime = 0 WHERE format = 'fb2'`),
  `Info.annotation` (по умолчанию null — второй `Info` в `Scanner` для «голых» файлов не менялся),
  `upsert` пишет колонку, `annotation(id)` читает её одним запросом при показе B12.
- `BookScreen.wrapAnnotation`: перенос по словам (`ink.measure`, Literata 40/400, ширина 1213.9),
  каждый абзац с новой строки, не больше 5 строк. Больше — последняя строка укорачивается по
  слову (`withEllipsis`, запятая/тире перед «…» не остаётся). Слово шире блока — `ink.ellipsize`.
  Строки считаются один раз в `onAttachedToWindow`, не в `render`. Зона касания «Читать полностью» —
  x 41…700, y 1660…1780 (кнопка в макете 95,1689 410×46).
- Замер снимка B12 (1404×1872): карточка y 1233…1792, заголовок 1284…1311, строки через 64
  (1351, 1416, 1476, 1540, 1608), кнопка 1698…1726, стрелка x 472…496 — как в макете.
- Прогон на книге: `adb install -r -d`, 5 тестовых FB2 в `/sdcard/Books/zz-ann/` (короткая, длинная,
  два абзаца, без аннотации, большая на 29 страниц), вход в B12 кликами (дебаг-входа в B12 нет):
  Главная → «Библиотека» → «Новые» → строка. Позиция: `PAGE_DOWN` ×4, `BACK`, «Читать полностью» —
  снимок читалки совпал с прежним и с «Продолжить чтение» (сравнение `ImageChops` по области текста).
  После проверки `rm -r /sdcard/Books/zz-ann`, скан убрал 5 строк (532 книги).
- Реальные данные: аннотация у 2 из 22 FB2 (Д.Браун, 1481 знак, абзацы через `\n`).
- Не сделано: EPUB (`dc:description`) — после метаданных CREngine; у DjVu карточки нет. EPUB и
  DjVu на книге отдельно не открывались: сканер читает аннотацию только у FB2, у остальных колонка
  `annotation` пуста, и по коду карточка не рисуется (`annLines` пусто).
