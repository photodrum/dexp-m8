# ТЗ: читалка оболочки DEXP M8 (CREngine + DjVuLibre)

> Версия от 2026-11-08, правки 2026-11-11. Решения согласованы с владельцем проекта:
> лицензия проекта — **GPL-2.0-only** (было AGPL-3.0: CREngine — GPL-2.0, MuPDF — AGPL-3.0, вместе в одном APK нельзя);
> **PDF и CBZ в читалке не поддерживаются** (владелец PDF на книге не читает), MuPDF убирается; DjVu — **сразу**;
> свой C-разбор FB2 остаётся — для сканера библиотеки; порядок — **сначала оболочка,
> потом читалка**, с короткой пробой движков (этап R0) в середине работы над оболочкой.
>
> Это ТЗ дополняет, а не отменяет уже сделанное: `EinkActivity`, `Screen`, `Ink`, `Tokens`,
> `D`, `Icons`, B1/B2 и C-ядро `core/book.c` остаются как есть. Как читать макеты —
> `docs/DESIGN_USAGE.md`.

## 1. Цель и архитектура

Свою постраничную вёрстку на C дальше не развиваем. Страницу книги рисует готовый движок,
всё вокруг неё — наш `Canvas` по макету Penpot.

| Слой | Чем делаем | За что отвечает |
|---|---|---|
| Интерфейс читалки | свой `Canvas` (как остальная оболочка) | колонтитулы, прогресс, меню, выделение, заметки, листы, диалоги, клавиатура |
| FB2, EPUB, MOBI, TXT, RTF, DOC | **CREngine**, ветка `koreader/crengine` | вёрстка страниц, переносы, сноски, оглавление, поиск, координаты слов |
| DjVu | **DjVuLibre** | страница картинкой, масштаб |
| PDF, CBZ | не поддерживаются | решение 2026-11-11; при необходимости CBZ — свой код на `java.util.zip` + `BitmapFactory` |
| Сканер библиотеки | своё C-ядро (`core/book.c`) для FB2; метаданные CREngine — для остальных | название, автор, серия, аннотация, обложка без открытия книги движком |
| Сетевые каталоги | свой OPDS 1.x-клиент на `XmlPullParser` | экраны B14–B18, B57, B64–B69 (это часть оболочки) |

Обвязку JNI к CREngine брать за образец у CoolReader (`buggins/coolreader`, модуль
`cr3engine`): она уже написана под Android. Обвязка KOReader на Lua не подходит.

```
 Экраны читалки (Kotlin, Canvas)            B3 B9 B10 B29 B50–B52 B27 B28 B30 B31 …
            │
            ▼
      ReaderEngine  ── один поток движка, два буфера Bitmap
       │             │
       ▼             ▼
   CrEngine      DjvuEngine                      (JNI, armeabi-v7a)
       │             │
  crengine       djvulibre                       (git-подмодули, CMake)

 Сканер библиотеки ── core/book.c (FB2) + метаданные движков ── SQLiteDatabase
```

Экраны обращаются только к `ReaderEngine` и базе библиотеки; какой движок открыл книгу,
интерфейс не знает.

## 2. Исходные данные и ограничения

Работа идёт в репозитории `denisle/dexp-m8` (ветка `main`). Все правила из `docs/` действуют,
кроме изменений ниже.

| Параметр | Значение |
|---|---|
| Устройство | DEXP M8 Prudentia, единственное целевое |
| Процессор / память | Rockchip PX30, 4×Cortex-A35; 1 ГБ ОЗУ, 16 ГБ flash |
| ОС / ABI | Android 8.1 (API 27), прошивка `armeabi-v7a` |
| Экран | E-Ink Carta 7,8″, 1404×1872 px, 300 ppi, 16 градаций |
| Единицы | дизайн-px макета (`D.u = screenW / 1404`, на книге 1.0) |
| Палитра | только G0…G15, шаг 17 |
| Макет | Penpot, файл «UI», страницы «v5» (B1–B76) и «v5 дизайн-система» |
| Лицензия | GPL-2.0-only для всего проекта (`LICENSE` в корне) |

**Что меняется в правилах проекта** (вступает в силу с этапа R0, до него код не трогаем):

- допускается C++ рантайм — CREngine написан на C++: `c++_static` (предпочтительно) или
  `c++_shared`;
- из roadmap снимаются «постраничная вёрстка на C» и «EPUB: zlib inflate + zip» —
  их делают движки;
- `abiFilters`: в release только `armeabi-v7a` (иначе три движка × три ABI раздуют APK);
  `arm64-v8a` и `x86_64` для debug и CI можно оставить, если сборка движков под них не мешает;
- шрифт Literata для текста книги кладётся **полным** (кириллица, латиница, знаки, курсив),
  а не subset'ом: движок рисует любые символы книги. Subset'ы Manrope для интерфейса
  остаются как есть.

Не меняется: без AndroidX/Material/Compose, одна `EinkActivity`, экраны — `View` с `onDraw`,
без анимаций, без полупрозрачности и размытия, объём слоями как в `Ink`.

## 3. Этапы

Читалка делается **после оболочки**. Исключение — короткая проба R0, её делают в середине
работы над оболочкой, чтобы заранее знать бюджет памяти.

Каждый этап сдаётся отдельной сборкой, проверенной на книге. Следующий начинается после
приёмки предыдущего.

### R0. Проба движков (2–3 дня, в середине работы над оболочкой)

Подключить `koreader/crengine` и DjVuLibre как git-подмодули (MuPDF был в пробе, снят 2026-11-11 — лицензия), собрать через CMake
под `armeabi-v7a` вместе с зависимостями (freetype, harfbuzz, libpng, libjpeg, zlib, fribidi,
libunibreak, utf8proc). Временный отладочный экран: открыть FB2, EPUB и DjVu,
отрисовать первую страницу в `Bitmap`, вывести на экран.

- Приёмка: на книге открываются FB2, EPUB и DjVu; в DEVLOG записаны PSS с открытой книгой,
  время отрисовки страницы, время первой разметки 5-МБ FB2, размер APK.
- **Решение «идём / не идём».** Если PSS > 60 МБ или страница дольше 300 мс и это не лечится
  настройками кэша — возвращаемся к выбору (своя вёрстка только для FB2 на `book.c`
  или KOReader через Intent). Решаем вместе.
- **Итог (7.4, 2026-11-12): «идём».** crengine и чёрно-белый DjVu — в пределах критериев; цветной DjVu ≈ 1,5 с/стр. принят (предзагрузка, индикатор; замер на реальном скане — в приёмку R2).

### R1. Чтение FB2 и EPUB

`ReaderEngine` + `CrEngine` (раздел 4). Экран B3 показывает настоящую страницу
с колонтитулами и прогрессом; листание; сохранение позиции; B58 при долгой первой разметке.

- Приёмка: «Анна Каренина» (FB2) и тестовый EPUB открываются, листаются вперёд и назад,
  позиция сохраняется при выходе и после перезапуска.

### R2. DjVu

`DjvuEngine` за тем же интерфейсом. B31 (масштаб кнопками, обрезка полей,
колонки, контраст — сверить с чатом дизайна, какие элементы остаются без PDF), B45 и B59 (ошибки). Жестов масштаба нет — только кнопки.

- Приёмка: DjVu из тестового набора открывается и листается;
  битый файл даёт экран ошибки, а не падение.

### R3. Навигация и настройки текста

B9 (меню чтения), B10 (оглавление), B29 (переход на страницу), B4 и B70 (шрифт, кегль,
интервал, поля, переносы), B39 (настройки по умолчанию, зоны касания).

- Приёмка: смена кегля перевёрстывает книгу и сохраняет место чтения (та же фраза
  на экране); переносы по русскому словарю работают; MOBI, TXT в CP1251, RTF открываются.

### R4. Выделение, цитаты, заметки, закладки, поиск

B50–B52, B27, B28. Долгое нажатие выделяет слово, маркеры расширяют выделение; цитаты,
заметки и закладки хранятся по позиции движка (xpointer для CREngine, страница+смещение
для DjVu), а не по номеру страницы.

- Приёмка: цитата остаётся на своём тексте после смены кегля; поиск находит все вхождения
  с номерами страниц (для DjVu поиска нет — нет текстового слоя).

### R5. Словарь и сноски

B30, B73. Слово под пальцем → словарь; `linkAt()` → сноска поверх страницы.

- Приёмка: сноска FB2 открывается и закрывается без потери места; словарь находит слово
  в начальной форме.

### R6. Чтение вслух

Кнопка «Вслух» в B9 через системный `TextToSpeech`. На прошивке без Google движка TTS может
не быть — сначала проверить `adb shell settings get secure tts_default_synth`; если пусто,
этап откладывается до выбора офлайн-движка.

- Приёмка: текущая страница читается вслух, листание идёт за чтением.

## 4. Интерфейс `ReaderEngine`

Один Kotlin-интерфейс для обоих движков. Реализации: `CrEngine`, `DjvuEngine`. Пакет — `ru.ogrpfsense.dexpm8.reader`, рядом с существующими `ui` и `core`.

```kotlin
interface ReaderEngine {
    fun open(path: String): OpenResult            // Ok(meta) | Error(code, message)
    fun close()

    // Вёрстка (только CREngine; DjVu игнорирует)
    fun setStyle(s: TextStyle)                    // шрифт, кегль, интервал, поля, переносы
    fun setViewport(w: Int, h: Int)               // область текста без колонтитулов

    // Страницы
    val pageCount: Int
    fun render(page: Int, into: Bitmap)           // рисует в готовый Bitmap, без аллокаций
    fun toc(): List<TocItem>                      // заголовок, уровень, страница, позиция

    // Позиции: стабильны при смене кегля
    fun positionOf(page: Int): Pos                // xpointer для CREngine, страница+смещение для DjVu
    fun pageOf(pos: Pos): Int

    // Текст на странице
    fun wordAt(page: Int, x: Int, y: Int): Range?
    fun rects(page: Int, r: Range): List<Rect>    // прямоугольники для выделения и подчёркивания
    fun text(r: Range): String
    fun search(q: String, limit: Int): List<Hit>  // фрагмент + страница + Range
    fun linkAt(page: Int, x: Int, y: Int): Link?  // сноска / внутренняя ссылка
}
```

Требования к мосту:

- все вызовы движка — в одном фоновом потоке (CREngine не потокобезопасен); UI только рисует
  готовый `Bitmap`;
- два буфера `Bitmap` на весь сеанс: текущая страница и заранее отрисованная следующая.
  Формат (`ALPHA_8` или `ARGB_8888`) выбрать по замеру памяти на R0;
- перед выводом страница сводится к 16 уровням серого (шаг 17) без дизеринга;
- кэш разметки CREngine — во внутренней памяти приложения; повторное открытие большой книги
  без пересчёта;
- ошибки движка возвращаются кодом, а не падением процесса; нативный crash ловится
  и показывает B45 (по образцу существующего `CrashScreen`);
- правило R8 `-keep class ... { *; }` для всех JNI-классов (урок из DEVLOG, п. 5);
- существующий `NativeBook` и `libdexp_core.so` не трогаем: сканер продолжает ими пользоваться.

## 5. Интерфейс читалки по экранам

Источник истины — Penpot, страница «v5»; компоненты — «v5 дизайн-система».
Порядок работы с макетом — `docs/DESIGN_USAGE.md`.

| Экран | Что делает | Этап |
|---|---|---|
| B3 «Чтение» | страница движка + колонтитулы + прогресс книги и главы | R1 |
| B58 «Открытие книги» | прогресс первой разметки длиннее 2 с | R1 |
| B31 «DjVu» | масштаб кнопками, обрезка полей, колонки, контраст (в макете «PDF и DjVu» — сверить) | R2 |
| B45, B59 «Ошибки» | файл не открылся / часть файла повреждена | R2 |
| B9 «Меню чтения» | верхняя и нижняя панели поверх страницы | R3 |
| B10 «Оглавление» | `toc()`, текущая глава подсвечена | R3 |
| B29 «Переход на страницу» | цифровая клавиатура, ползунок, «вернуться» | R3 |
| B4, B70 «Настройки текста» | шрифт, кегль, интервал, поля, переносы → `setStyle` | R3 |
| B39 «Чтение по умолчанию» | настройки для новых книг, зоны касания | R3 |
| B50–B52 «Выделение» | маркеры, меню действий, заметка с клавиатурой, метки на полях | R4 |
| B27 «Закладки и заметки» | список из базы, переход по `Pos` | R4 |
| B28 «Поиск по книге» | `search()`, результаты со страницами | R4 |
| B30, B73 «Словарь и сноски» | слово под пальцем, `linkAt()` для сносок | R5 |

Общие правила:

- **зоны касаний** — по настройке B39 (классическая / две половины / только вперёд);
  кнопки громкости листают;
- **нажатие видно сразу**: на `ACTION_DOWN` кнопка перерисовывается вдавленной через
  `invalidate(rect)`;
- **одна геометрия для рисования и касаний**: компонент сам знает свой прямоугольник;
- **выделение** — заливка G12 под текстом; цитата — подчёркивание G3 4 px; заметка —
  заливка G13 + номер на полях (макеты B50–B52 приведены к палитре 2026-11-08);
- **листы и диалоги поверх страницы без затемнения**: всё под ними перерисовывается
  на 4–5 ступеней светлее (текст G1 → G8), как на B51 и B53–B59.

## 6. Нефункциональные требования

Цифры проверяются на книге и записываются в DEVLOG на каждом этапе. Если замер R0 покажет
другое, цель пересматриваем вместе.

| Требование | Цель | Как проверять |
|---|---|---|
| Память в режиме чтения | PSS ≤ 60 МБ (оболочка без книги — по-прежнему ≤ 35 МБ, сейчас 18) | `dumpsys meminfo`, «Война и мир» открыта |
| Листание | ≤ 300 мс от касания до начала обновления экрана | лог с отметками времени; следующая страница готова заранее |
| Первое открытие книги 5 МБ | ≤ 60 с, с экраном B58 | таймер в логе |
| Повторное открытие | ≤ 2 с (из кэша) | таймер в логе |
| Падения | 0 на тестовом наборе | прогон всех книг раздела 7 |
| Размер APK | записать, без жёсткой границы | DEVLOG |

**Обновление E-Ink:** листание — частичное обновление; полное — каждые N страниц
по настройке B37 (по умолчанию 6) и при смене экрана. Кнопки, меню, выделение — только свой
прямоугольник. Режимы контроллера Rockchip исследуются отдельно и не блокируют этапы.

**Сборка:** в CI добавляется шаг сборки нативных библиотек движков. Проверка «пиксель
в пиксель»: `adb exec-out screencap -p` поверх экспорта борда из Penpot.

**Лицензии:** проект — **GPL-2.0-only** (решение 2026-11-11). CREngine — GPL-2.0 (в `README.TXT`;
«or any later version» только в 3 файлах из 115, поэтому считаем only), DjVuLibre — GPL-2.0-or-later.
MuPDF (AGPL-3.0) в проект не входит: с GPL-2.0-only он несовместим. FreeType берём по GPL-2.0 или FTL.
Запрос мейнтейнерам crengine про «or later» — по желанию, не блокер. Исходники открыты (GitLab, GitHub). Список библиотек
с лицензиями — экран B75 «Лицензии»; тексты лицензий шрифтов — `tools/fonts/OFL-*.txt`.

## 7. Приёмка

Этап сдан, когда сборка стоит на книге, критерии из раздела 3 выполнены на тестовом наборе,
а в DEVLOG записаны замеры из раздела 6 и sha256 APK.

**Тестовый набор** (`/sdcard/Books/test/` на книге):

| Файл | Что проверяет |
|---|---|
| «Анна Каренина», FB2 | базовое чтение, переносы, сноски |
| «Война и мир», FB2, ≥ 5 МБ | память, время первой разметки, кэш |
| Сборник стихов, FB2 | блоки `poem`, эпиграфы |
| EPUB 2 и EPUB 3 с CSS и картинками | стили, изображения, оглавление |
| MOBI без DRM, TXT в CP1251, RTF | кодировки и редкие форматы |
| DjVu | скорость отрисовки |
| Обрезанный FB2 и пустой файл | экраны ошибок B45 и B59, без падения |

**Не входит:** PDF и CBZ, альбомная ориентация (макеты будут позже на отдельной странице), OPDS 2.0,
DRM, синхронизация прогресса между устройствами.

**Запасной вариант:** если R0 не проходит по памяти или скорости, книги временно открываются
в KOReader через Intent; оболочка, библиотека и OPDS остаются своими. Решаем вместе.
