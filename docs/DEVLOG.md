# Журнал разработки

## 2026-11-08 — решение по читалке и порядок работ

**Читалка = свой UI + готовые движки.** Своя постраничная вёрстка на C и свой EPUB
(zlib + zip) сняты с плана. Страницы рисуют CREngine (FB2, EPUB, MOBI, TXT, RTF, DOC),
MuPDF (PDF, CBZ) и DjVuLibre (DjVu) за общим Kotlin-интерфейсом `ReaderEngine`.
PDF и DjVu входят в первую версию читалки. `book.c` остаётся — для сканера метаданных FB2.

**Порядок: сначала оболочка, потом читалка.** Исключение — проба движков R0 на 2–3 дня
в середине работы над оболочкой: собрать движки, открыть книги, замерить память и скорость,
решить «идём / не идём».

**Лицензия проекта — AGPL-3.0.** Совместима с CREngine, DjVuLibre и MuPDF, как у KOReader.

Новый `docs/READER_SPEC.md` (ТЗ, этапы R0–R6, приёмка). Обновлены `CONTEXT.md` (roadmap),
`ARCHITECTURE.md`, `COMPARISON.md`, `README.md`. Код и сборка не менялись.

## 2026-11-07 — этап 1: каркас оболочки и C-ядро

**Снятие дизайна с Penpot.** Прочитана страница v5 файла «UI»: 46 бордов 1404×1872.
Проверена палитра по всем бордам — фактически используются ровно 16 градаций с шагом 17,
посторонних цветов нет. Снята геометрия B1 и B2 до пикселя, выгружена геометрия 63 иконок
(каждая — два слоя: блик `#FFFFFF` `+3,+3` под контуром).

**Отказ от dp в пользу дизайн-px.** В ТЗ была формула «1 pt ≈ 4.2 px», по которой ширина
экрана выходила `334 dp` вместо реальных `702 dp` — вся вёрстка стала бы вдвое мельче.
4.17 = `300 ppi / 72` (типографский пункт), а dp считается от 160. Решение: рисовать
в пикселях макета, масштабируя `Canvas` один раз через `D.u = screenW / 1404f`.

**UI без единой зависимости.** Ни AndroidX, ни Material, ни Compose, ни RecyclerView.
`EinkActivity` — единственная Activity, экраны — `View` в стеке, переходы без анимаций,
свой статус-бар, `immersive`. Экономия PSS на PX30 с 1 ГБ — главный аргумент.

**Иконки числовой геометрией.** Вместо SVG в assets и Bitmap на все плотности — примитивы
в `IconSpecs.kt` (rectangle / ellipse / path), парсятся один раз, `Path` кэшируются.
Ноль байт в APK, всегда резкие, толщина штриха не плывёт.

**C-ядро разбора FB2.** Свой потоковый токенизатор вместо libxml2/expat: один проход,
стек тегов, текстовая арена на документ. Книга 5 МБ даёт ~2 МБ блоков, а не 50 МБ DOM.

### Найденные баги (исправлены)

1. `buf_normalize` в `book.c`: при нераспознанной сущности не сдвигался индекс — бесконечный цикл.
2. `Tokens.kt`: `R` не виден из пакета `ui` без явного `import ru.ogrpfsense.dexpm8.R`.
3. `Ink.paragraph`: `lastSpace` присваивался после проверки → мёртвая ветка переноса.
4. **Дефисы в именах ресурсов запрещены.** `res/font/manrope-700.ttf` проходит `aapt2`
   напрямую, но Gradle падает: только `a-z0-9_`. Переименовано в `manrope_700.ttf`.
5. **R8 удалял JNI-класс.** `-keepclasseswithmembernames ... native <methods>` разрешает
   shrinking: пока `NativeBook` никто не вызывает из Kotlin, он вылетает из APK и JNI
   падает на `UnsatisfiedLinkError`. Нужен `-keep class ... { *; }`. Проверено: было
   0 упоминаний в release-dex, стало 21.
6. `aapt2` требует `package` в `<manifest>`, а AGP 8 его вырезает (берёт из `namespace`).
7. `d8` — шелл-обёртка, ищет `java` в `PATH`.

### Окружение сборки

Поставлено без sudo в `~/.local`: JDK 17.0.21 (Temurin), Android SDK (platforms 27 и 34,
build-tools 34.0.0, NDK r26d, CMake 3.22.1, platform-tools), Kotlin 1.9.24, Gradle 8.7.
Gradle скачал CMake сам при первой сборке.

- `assembleDebug` — 965 КБ, внутри `lib/arm64-v8a/libdexp_core.so` (12 КБ) и `x86_64`.
- `assembleRelease` (R8) — 145 КБ, JNI-класс сохранён.

## 2026-11-07 — первый запуск на железе

**Книга 32-битная.** `ro.product.cpu.abi` = `armeabi-v7a`. Первая сборка содержала только
`arm64-v8a` и `x86_64`, установка упала:

```
Failure [INSTALL_FAILED_NO_MATCHING_ABIS: Failed to extract native libraries, res=-113]
```

Причина: PX30 — 64-битное железо, но прошивка Android 8.1 собрана под arm32. В
`abiFilters` добавлен `armeabi-v7a`, пересборка — `BUILD SUCCESSFUL`, в APK три
библиотеки: `armeabi-v7a` (8 020), `arm64-v8a` (12 000), `x86_64` (11 696). Размер 981 369.

### Причина трёх «сбоев подряд» и урок

Падение было одно и то же: `IndexOutOfBoundsException` в `Icons.parseSvg$flush`.
Команда пути определялась по длине токена (`s.length == 1`), поэтому однозначные
координаты вроде `1` в `M1,2` принимались за команду, после чего `flush()` вызывался
с пустым списком чисел. Тест `tools/check_path_parser.py` показал: падали **все 44**
пути иконок — приложение было обречено с первой секунды.

Но настоящая проблема была в **процессе**, а не в коде:

1. Первые сборки проверялись только на компиляцию, а не на выполнение. Отсюда два
   бага, которые «ловились бы» тестом на данных: ABI и парсер путей.
2. **На книгу три раза ставился старый APK.** Скачанные файлы попадали в `Загрузки`,
   а `adb install app-debug.apk` из `C:\platform-tools` ставил файл, лежавший в этой
   папке с первой установки. Признак, по которому это вскрылось: номер строки в стеке
   (`Icons.kt:89`) не совпадал с текущим исходником, где на этой строке уже стоял
   заголовок функции.

Правила, введённые после этого:

- **уникальное имя файла** при каждой сборке: `dexpm8-YYYYMMDD-HHMM.apk`, чтобы
  скачанный APK нельзя было перепутать со старым;
- **sha256 в документации** — сверять, что установлен именно тот файл;
- после установки проверять `adb shell dumpsys package ... | findstr lastUpdateTime`;
- офлайн-тесты на данных (`check_icons.py`, `check_path_parser.py`) прогоняют реальные
  спеки через ту же логику, что в Kotlin, до установки на книгу.

### Память: 18 МБ PSS

```
adb shell dumpsys meminfo ru.ogrpfsense.dexpm8 | findstr /C:"TOTAL PSS"
TOTAL  18417  10528  1560  0  11345  8119  3225
```

**18 417 КБ.** Вдвое лучше поставленной цели (35 МБ).

Разбор: 18 417 — PSS всего, 10 528 — private dirty (своя память процесса),
1 560 — private clean, 11 345 — heap size, 8 119 — heap alloc (занято объектами),
3 225 — heap free (свободный запас).

Вывод: 8 МБ занято объектами, 3 МБ свободно — резерв есть, но небольшой. При добавлении
библиотеки со сканером и читалки следить, чтобы PSS не вышел за 35 МБ.

Что дало результат: ни AndroidX, ни Material, ни Compose; UI — единственный `Canvas`
с переиспользуемыми `Paint`/`RectF`/`Path`; иконки — числовые примитивы вместо битмапов;
шрифты — 5 subset'ов по 38 КБ; в рендере ноль аллокаций на кадр.
