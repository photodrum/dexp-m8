# DEVLOG 2026-11-19 — B71 «Часовой пояс»

Подробности к записи `docs/DEVLOG.md` (п. 13, экран B71). Модель — Opus (Act).

## Что сделано

- `core/Sys.kt`: `zone()`, `autoZone()`, `setZone(id)`. Свойство `persist.sys.timezone`, доступ
  рефлексией к `android.os.SystemProperties` — тем же приёмом, что контраст (`gamma`).
- `core/Zones.kt` — **24 пояса мира** (решение человека 2026-11-19) и подпись пояса `label(id)`
  для B41/B60. Раньше подпись собиралась двумя копиями `zoneName` в этих экранах; копии убраны.
- `ui/SetTimeZoneScreen.kt` — B71: тумблер «Определять по сети» 41,250 1321×160 (как в макете,
  только чтение) и панель 41,466 1321×1300 с 24 поясами сеткой 2×12, шаг строк 106.

## Решения

1. **`AlarmManager.setTimeZone` из CONTEXT не подходит.** Он требует `SET_TIME_ZONE` — право
   уровня подписи платформы, `WRITE_SETTINGS` его не заменяет.
2. **`setprop` из процесса приложения работает.** Проверено из `run-as` (uid 10052):
   `setprop persist.sys.timezone …` меняет время сразу, значение ложится в
   `/data/property/persist.sys.timezone` и переживает перезагрузку. `su` приложению недоступен
   (`Permission denied`), и он не нужен.
3. **Кеш зоны в процессе сбрасывается вручную.** `TimeZone.getDefault()` кеширует пояс, а
   рассылка `TIMEZONE_CHANGED` после `setprop` не приходит (её шлёт только `AlarmManager`, и она
   защищённая). Без `TimeZone.setDefault(null)` часы статус-бара оставались в старом поясе
   (на снимке 4:26 против `date` 23:26). После правки часы совпадают с `date`.
4. **24 пояса вместо 418 городов и вместо 11 поясов России.** 418 зон tzdata дают 63 «часовых
   поведения», по круглым часам — ровно 24 (UTC−11 … UTC+12). Отсюда сетка 2×12 на одной
   странице: 70 страниц плоского списка отвергнуты человеком как неудобные.
5. **Пояс с переходом на летнее время — отдельная строка** с подписью «летом UTC+N»: Лагос
   (UTC+1 круглый год) и Берлин (UTC+1 / UTC+2) иначе слились бы, и летом у одного из них время
   было бы неверным. Представитель пояса выбран так, чтобы подпись не врала: Гонолулу, Финикс,
   Богота, Каракас, вся Россия — города без перехода.
6. **Нецелые пояса не делаем** (решение 2026-11-19): Индия +5:30, Непал +5:45, Иран +3:30,
   Афганистан +4:30, Мьянма +6:30, Дарвин +9:30, Лорд-Хау +10:30, Chatham +12:45, Ньюфаундленд
   −3:30, Маркизские −9:30, Евкла +8:45.
7. **«Определять по сети» остаётся** (решение 2026-11-19) — как в макете, только чтение:
   `Settings.Global.auto_time_zone` пишется лишь с `WRITE_SECURE_SETTINGS`, на книге `settings put`
   из процесса оболочки отказывает (`Security exception: You need MANAGE_USERS`). Тумблер
   показывает состояние системы (на книге 1), касание по строке не реагирует — как «Время по сети»
   на B41.

## Грабля tzdata книги (важно для будущих правок)

tzdata Android 8.1 старая. `America/Sao_Paulo` отдаёт **UTC−2**, потому что в ней ещё действует
летнее время Бразилии (отменено в 2019). Поэтому представитель UTC−3 — `America/Buenos_Aires`.
Все 24 представителя проверены на книге перебором `setprop` + `date`: смещения совпали.

## Грабли окружения

- Heredoc в терминале Cline подвисает — JSON макета разбирать `grep -o '"tx":…'`, а не Python.
- `editor` с `insert_line` вставлял текст не туда, если файл уже заканчивался на `}`; после
  вставки остался хвост дубля. Файл теперь пересоздаётся целиком, хвосты проверяются глазами.
- `input tap` бьёт по физическим px, а `ROW_Y` в дизайн-px: при шаге 106 строка i в колонке
  лежит на `490 + 106·i`. Ошибка в расчёте даёт соседнюю строку, а не «экран не работает».

## Правка по замечанию: галочка выходила за плашку (2026-11-19)

Замечание человека со снимка: галочка текущего пояса стояла вне панели. Причина — отступ
галочки считался от правого края панели (1362), а колонка кончалась раньше: `780 + 560 + 44 = 1384`,
то есть на 22 px правее панели. Исправлено: у каждой колонки свой край галочки —
`CHECK_X = [622.2, 1282.7]`, правая совпадает с макетом B71 (правый край 1324.7, до панели 37 px),
левая зеркальна. Текст занимает всю колонку (`COL_W = 572`), а сужается только у строки с
галочкой (`CHECK_X − x − 24`) — иначе обрезалось «Петропавловск-Камчатский», как было в первом
варианте правки. Проверено на книге: галочка у «Москвы» (правая колонка) и у «Паго-Паго»
(левая) — внутри плашки, длинное описание Камчатки целиком.
