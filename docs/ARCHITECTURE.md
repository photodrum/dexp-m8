# Архитектура и результаты исследования

## Ограничения платформы

| | |
|---|---|
| SoC | Rockchip PX30, Cortex-A35 ×4 |
| **ABI прошивки** | **`armeabi-v7a`** — система 32-битная, несмотря на 64-битное железо |
| ОЗУ / flash | 1 ГБ / 16 ГБ, карты памяти нет |
| ОС | Android 8.1 Oreo, API 27, без Google Play |
| Экран | 7.8″ E-Ink Carta, 1404×1872 px, 300 ppi, 16 градаций, сенсор |
| Связь | Wi-Fi, Bluetooth, USB Type-C, без разъёма 3.5 мм |

**Про ABI.** Проверено на устройстве: `ro.product.cpu.abi` = `armeabi-v7a`. Первая сборка
содержала только `arm64-v8a` и `x86_64` — установка упала с
`INSTALL_FAILED_NO_MATCHING_ABIS (res=-113)`. Теперь `abiFilters` включает
`armeabi-v7a`, `arm64-v8a`, `x86_64`; для книги работает первая.

Следствия для архитектуры: каждый мегабайт PSS на счету; тяжёлые UI-фреймворки
не окупаются; сборка мусора на 1 ГБ заметна, поэтому в рендере ноль аллокаций на кадр.

## Как отрисовывается интерфейс

E-Ink не умеет показывать промежуточные состояния: любая анимация превращается в
последовательность полных перерисовок с мерцанием. Поэтому UI строится на трёх правилах:

1. **Экран — это `View` с `onDraw`.** Не иерархия виджетов, а один `Canvas`.
   Нет `measure`/`layout`-проходов, нет `requestLayout`, нет пересчёта дерева.
2. **Смена экрана — полная перерисовка.** Никаких `Animator`, `TransitionManager`,
   `overridePendingTransition` — они отключены на уровне темы окна.
3. **Касание — «нажал и отпустил».** `ACTION_MOVE` дальше 40 px отменяет нажатие.
   Скролл и pinch не распознаются вовсе: листание только кнопками.

### Дизайн-пространство

```
D.u = screenWidthPx / 1404f        на книге = 1.0
canvas.scale(D.u, D.u)             дальше весь рендер в числах макета
```

Все геометрические константы в коде — это числа из Penpot. Отступ 41 в макете —
`41f` в коде. Пропорции не плывут ни на какой ревизии экрана.

### Слои объёма

Blur и `elevation` запрещены — они дают градиент, который E-Ink дизерит в шум.
Объём делается ступенчатыми слоями, точно как в макете:

```
выпуклая:    G10 @ +5,+10   →  G15 @ 0,0  →  G14 @ +3,+3 (W-5, H-10)
вдавленная:  G15 @ 0,0      →  G10 (W-3, H-3)  →  G12 @ +3,+5 (W-6, H-8)
тёмная:      G8  @ +5,+10   →  G6  @ 0,0  →  G3  @ +3,+3
```

### Типографика

Manrope для интерфейса (400/600/700/800), Literata для текста книги (400).
Шрифты подключаются как ресурсы (`res/font/`), `Typeface` кэшируется по весу.
`isSubpixelText = false` — на E-Ink субпиксельный рендер только мылит.

## Читалка (план, решение 2026-11-08)

Полное ТЗ — `docs/READER_SPEC.md`. Делается после оболочки; проба движков (R0) —
в середине работы над оболочкой.

**Страницу книги рисует готовый движок, всё вокруг — наш `Canvas`.** Колонтитулы, меню,
оглавление, выделение, листы и диалоги — те же `Screen`/`Ink`/`Tokens`, что в оболочке.

| Форматы | Движок |
|---|---|
| FB2, EPUB, MOBI, TXT, RTF, DOC | CREngine (`koreader/crengine`, JNI по образцу CoolReader `cr3engine`) |
| PDF, CBZ | MuPDF |
| DjVu | DjVuLibre |

```
Экраны читалки ─► ReaderEngine ─► CrEngine | MuPdfEngine | DjvuEngine ─► JNI ─► движки (C/C++)
Сканер библиотеки ─► NativeBook / book.c (FB2) + метаданные движков ─► SQLiteDatabase
```

- Пакет `ru.ogrpfsense.dexpm8.reader`; `ui` и `core` не меняются.
- Все вызовы движка — в одном фоновом потоке; UI выводит готовый `Bitmap`.
  Два буфера на сеанс (текущая и следующая страница), без аллокаций на кадр.
- Страница перед выводом сводится к 16 уровням серого без дизеринга.
- Позиции (закладки, цитаты, заметки) — по внутренней позиции движка (xpointer),
  а не по номеру страницы: переживают смену кегля.
- Своё C-ядро `book.c` остаётся — для быстрого сканера метаданных FB2; страницы им
  больше не верстаются.

Что меняется в сборке с этапа R0: допускается C++ рантайм (`c++_static`); в release
`abiFilters` только `armeabi-v7a`; Literata для текста книги — полный шрифт, не subset.
Бюджет памяти: оболочка ≤ 35 МБ PSS (сейчас 18), чтение ≤ 60 МБ.

Лицензия проекта — AGPL-3.0 (совместима с CREngine, DjVuLibre и MuPDF).
