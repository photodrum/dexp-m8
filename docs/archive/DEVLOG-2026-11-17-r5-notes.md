# 2026-11-17 — R5.1: натив сносок, вкладка «Сноска» листа B30

Пункт 18 `docs/ROADMAP.md` (R5). Натив: `cre_session.cpp`, `reader_jni.cpp`; Kotlin:
`Engine.kt`, `DictSheet.kt`, `ReaderScreen.kt`, `EngineSelfTest.kt`.

## Со стороны движка

Сноска в FB2 — обычная внутренняя ссылка: `<a l:href="#n_1">1</a>` в тексте и
`<section id="n_1">` в конце книги. Руками HTML не разбираем:

- `ldomXPointer::getHRef` (`lvtinydom.cpp`) сам поднимается по родителям до `<a>` и
  отдаёт `href` для любой точки внутри ссылки (`LXML_NS_ANY` — префикс `l:` не мешает);
- `ldomDocument::getElementById` ищет по индексу `id`-атрибутов (`_idNodeMap`,
  `onAttributeSet`) — тот же путь, которым ходит сам crengine в `LVDocView::goLink`.

Новые точки входа (`cre_session.cpp`):

- `dexp_reader_link_at(x, y, out, outLen)` — `getNodeByPoint(..., false, true)` →
  `getHRef` → якорь БЕЗ решётки; `0` — под точкой не ссылка, `< 0` — код ошибки.
  `forTextSelection=true` — как у `dexp_reader_word_at`: иначе касание края абзаца не
  даёт узла.
- `dexp_reader_link_text(href, out, outLen)` — якорь (`n_1` или `#n_1`) →
  `getElementById` → текст обходом дерева. Ведущий номер («1. …») отрезается.
- `dexp_reader_link_rects(out, outLen)` — отрезки ссылок текущей страницы в окне,
  для самотеста (координат значка сноски в тексте страницы нет).

JNI: `linkAtNative` (буфер 512), `linkTextNative` (4 КБ — как цитата B50),
`linkRectsNative` (`int[]` по 4 числа на отрезок, как у `rectsNative`).

## Грабли (все — проверены на книге)

- **`ldomNode::getRect` не существует.** Рамку даёт `ldomXPointer::getRect`, но для
  элемента `<a>` она **вырожденная**: у ссылки `#n_1` в тестовой книге вышло
  `1244,197..1245,281` — ширина 1 px, кончик пера. Точкой в 1 px сноску не взять.
  Правильно — диапазон по всему узлу (`ldomXRange range(node)`) и
  `getSegmentRects`: по отрезку на строку, ровно как у выделения B50
  (`1244,197..1289,281` — 45×84).
- **Счётчик накопленного нельзя передавать по значению** в рекурсию: родительский
  вызов после детей перезаписывал `g_linkRects` своим нулём, и все отрезки «исчезали»
  (в отладке видно `href=3, с рамкой=3`, а `-> 0`). Теперь `int &n`.
- **`href` бывает двух видов** — с решёткой (из `getHRef`) и без (`toc`, свой же
  `link_at`). Первая версия `href_anchor` требовала `#`, и `linkText("n_1")` молча
  возвращал 0: лист показывал «Сноска пуста». Теперь решётка необязательна, а внешний
  URL (`://` или `/`) отбрасывается.
- **`el_title` / `attr_href` в `cre_session.cpp` не видны** без `#include "fb2def.h"`:
  перечисления `el_*`/`attr_*` объявляются только там (`lvdocview.cpp` включает так же).
  Без него — сравнение по имени строкой, и `attr_href` просто нет.
- **Вспомогательные функции не должны попадать в `extern "C"`**: `href_anchor`
  возвращает `lString32`, и компилятор ругался `-Wreturn-type-c-linkage`. Обе функции
  (`href_anchor`, `node_text`) перенесены в безымянное пространство имён выше блока.

## Со стороны экрана

- `Engine.linkAt(page, x, y)` — как `wordAt`: сначала `syncPage(page)`, иначе `prefetch`
  оставил бы движок на соседней странице и ответ пришёл бы про неё (та же грабля, что
  чинили для удержания в R5.2а).
- `ReaderScreen.onLongPress` берёт якорь **тем же касанием**, что и слово (`selHref`):
  у вкладки «Сноска» нет ни сети, ни второго запроса к движку. `selHref` сбрасывается
  везде, где снимается выделение: `clearSelection`, листание, `onBackPressed`,
  `onDetachedFromWindow`.
- `DictSheet` получил **отдельные поля на вкладку**: `dict*` (словарь), `tr*` (перевод),
  `note*` (сноска). Раньше общие `grammar/body/source` затирали друг друга — вернувшись
  со «Сноски» на «Словарь», человек увидел бы сноску вместо статьи. Чтение — через
  `grammar()/bodyText()/sourceText()/waiting()` по открытой вкладке.
- Тексты вкладки: ожидание `WAIT_NOTE` («Ищу сноску…»), «Это слово не ссылка: сноски в
  книге нет.», «Сноска в книге пустая.», подпись источника «Сноска книги».

## Проверка

Тестовая книга `app/src/main/cpp/test/testdata/notes.fb2` — три сноски в одну главу
(`#n_1`…`#n_3`), положена на книгу как `/sdcard/Books/notes-test.fb2`.

Самотест (`EngineSelfTest.noteStep`, добавлен в `findStep`):

```
reader: linkRects page 0 -> 3
selftest: сноска стр.0 отрезков=3 точка 1266,239 → #n_1
reader: linkText #n_1 -> 92 симв.
selftest: сноска #n_1 текст='Сноска первая: о счастливых семьях говорит всякое.' ок
```

На книге без ссылок: `linkRects page 1 -> 0`, `сноска — на просмотренных страницах
ссылок нет` — «молчит», как и должно.

Экран (6IVJ8C68AP, «Воскресение»): удержание «солнцем» → B50 → «Словарь» → лист B30 со
статьёй «солнце» → вкладка «Сноска» → «Это слово не ссылка: сноски в книге нет.»
(сноски в этой главе нет). Снимки: `build/shots/b30_note_tab.png`.

`typecheck` 225/0, `check_design` 331/0, `assembleDebug` — успешно.

## Замечание на будущее

Зона шторки B5 в читалке (`y < 513`, `x` 468…936) перекрывает **верх** меню B50: если
выделенное слово в верхней трети страницы, отпускание по кнопке меню открывает шторку,
а не меню (проверено 2026-11-17: касание 684,400 → `shade: open`). К R5.1 отношения не
имеет — это порядок проверок в `Screen.onTouchEvent` (`inShadeZone` раньше `onUp`).
Выделение ниже зоны работает штатно.
