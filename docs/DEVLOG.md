## 2026-11-10 — п. 3, шаг 3.9г: очистка E-Ink после диалога права (`EinkActivity`, Opus)

Замечание 4. Причина: окно под системным диалогом не перерисовывается. После закрытия диалога
система возвращает старый кадр, а контроллер быстро обновляет только место диалога, поэтому
«ОТКЛОНИТЬ» остаётся следом. `invalidate()` даёт тот же кадр — следа он не снимает.
Решение: `onWindowFocusChanged(false)` при `storageAsking` ставит `cleanOnFocus`; при возврате
фокуса `cleanRefresh()` кладёт поверх `host` белый `View` G15 (касания съедает), через
`CLEAN_MS` = 300 мс `endClean()` убирает его и делает `invalidate` экрана. Получается два
мигания, но только после диалога права. В трассе: `eink: clean after dialog`.
Порядок событий Android: `onRequestPermissionsResult` → `onResume` → фокус. Слушатель права
перерисует экран под белым кадром, на панель это не попадёт.
Грабли: после «Больше не спрашивать» система, вероятно, всё равно на миг запускает
`GrantPermissionsActivity` без диалога — если фокус при этом уйдёт, будет лишний белый кадр (безвредно).
Переход экрана за эти 300 мс (`changeTo` → `removeAllViews`) снимет белый кадр сам.
Sysfs/драйвер Rockchip не трогали (это п. 6). `tools/typecheck.sh`: 0 ошибок, 46 классов.
На книге не проверено (3.10): нет ли следа; если есть — увеличить `CLEAN_MS` до 450–600.

## 2026-11-10 — п. 3, шаг 3.9б: пауза между сканами и «Идёт поиск книг…»

`scanner.isRunning` показывает «Идёт поиск книг…» / «Это займёт несколько секунд». После прохода
`refresh/layout/redraw` как раньше. mtime вложенных папок не меняется — основная защита пауза.
