## Решения

- **Тихая.** Автопроверка не открывает B76 и ничего не качает: единственный видимый след —
  строка «Последняя проверка — сегодня, 21:08 · обновлений нет» на B43. Иначе при каждом
  старте на E-Ink был бы лишний кадр и вопрос «что это было».
- **Неделя считается от `updateCheckedAt`**, общий для ручной и авто. Ручная проверка на B76
  тем самым отодвигает недельный срок — иначе человек, проверивший вручную, получил бы
  автоматическую на следующем же запуске.
- **Неудачу не пишем.** `fetch` вернул `null` — `updateCheckedAt` не двигаем, `updateResult`
  остаётся прежним, а следующий старт пробует снова. Писать «сервер не ответил» в строку B43
  шумно: автопроверка идёт на каждом старте, пока сети нет.
- **`updateSkipCode` не навязываем.** Версию, отложенную «Позже», автопроверка отмечает
  словами «версия N отложена» — экран не открывается, но и «обновлений нет» врать не станет.
- **Мастер первого запуска — пропуск.** Пока на экране B60, сеть ещё могут не настроить;
  проверка пойдёт на первом обычном старте.
- **Тумблер выключен — не ходим в сеть вообще**, даже чтобы узнать про Wi-Fi.

## Грабля

1. **`pm clear` на книге сносит данные целиком** — базу и `shell.xml`. Процедура восстановления
   в `docs/BUILD.md`, «Смена подписи без потери данных» (шаги 3–4); бэкап — `~/dexpm8-backup-<дата>`.
   Для проверки первого запуска достаточно `--es screen first`, без `pm clear`.
2. **`sed -i` по `/data/data/.../shell.xml` из `adb shell` — `Permission denied`:** правами владельца
   обладает только `run-as`, поэтому порядок — `exec-out run-as … cat > /tmp`, правка, `run-as … sh -c 'cat >'`.
3. **Подмена `update_checked_at`** — самый быстрый способ проверить «неделю»: `date +%s` минус
   8×24×3600 и запись в `shell.xml`; на живом процессе файл перезапишется из памяти, поэтому
   сначала `am force-stop`.
