## 2026-11-13 — П. 10, шаг 10.10: B57 «Нет подключения» (Sonnet)

- **Зачем.** Кэш фида появился ещё в 10.8 (`Opds.fetch` при отсутствии сети отдаёт последний удачный фид), но экран молчал: пользователь видел либо старые строки как свежие, либо карточку B44 «Не удалось открыть / Нет подключения». По макету причина называется диалогом B57 поверх затемнённого B16.
- **`ui/NoNetDialog.kt`.** Числа из `design/v5/B57.json`: диалог 92,610 1225×662 (выпуклая, r 56), гнездо 152,674 140×140 (дно G12) + `wifi@49.6x52`, заголовок «Нет подключения» 332,680 60/700, подзаголовок «Каталог «…»» 32/600 G4, пояснение 152,880 38/500 lh 1.4 (перенос), «Повторить» — выпуклая 152,1071 425×112, «Настройки Wi-Fi» — тёмная 612,1056 645×142. Ширина подзаголовка — рамка макета 543, а не 940.
- **Когда диалог.** Флаг `offline` — это только «сети нет совсем»: `Opds.online()` спрашивается в фоновом потоке **до** `fetch`/`search` (сам `fetch` при отсутствии сети молча отдаёт кэш, и по ответу этого не видно). Отказ сервера (404, 500, «неверный пароль») остаётся причиной в карточке B44 — это не «Wi-Fi выключен», и диалог B57 о ней врать не должен.
- **`OpdsScreen`.** Экран затемняется `dimBegin` (замечание 15: статус-бар и диалог не темнеют), под диалогом — последний фид из кэша, как в макете. Карточка «Не удалось открыть» под диалогом не рисуется (`rows.isEmpty() && !offline`), иначе «Нет подключения» стоит дважды. Пока диалог открыт, экран под ним не нажимается; живыми остались две кнопки и «Назад» в шапке — иначе с экрана не уйти.
- **Кнопки.** «Повторить» повторяет **тот же** запрос: поиск повтором `runSearch(curSearch)`, иначе фид `curUrl` с прежним `root`. Для этого пришлось завести `curSearch`/`curRoot`: после неудачи `searchFor` обнуляется, и повтор ушёл бы в фид вместо поиска. «Настройки Wi-Fi» — `Settings.ACTION_WIFI_SETTINGS`; по возврату (`onWindowFocusChanged`, флаг `waitNet`) — `cleanScreen()` (след системного экрана на E-Ink) и тот же повтор, даже если сети нет: так видно, что приложение её проверило.
- **Грабли.** (1) Двойное отрицание: написал `setOffline(!on)` при том, что внутри уже `v = !net`, — диалог вылезал при включённом Wi-Fi; ловится только на книге, `typecheck` и `assembleDebug` молчат (компилируется, логика не та). (2) `tools/typecheck.sh` не находит `java`, если `~/.local/jdk/bin` не в `PATH` — запускать `PATH="$HOME/.local/jdk/bin:$PATH" bash tools/typecheck.sh`; Gradle так же (`JAVA_HOME`).
- **Проверено на книге 2026-11-13** (BookLore, 8 разделов): Wi-Fi включён — диалога нет, 5 разделов и «1 / 2»; `svc wifi disable` → диалог «Нет подключения · Каталог «Grimmory Catalog»» поверх затемнённого B16 с фидом из кэша, совпадает с макетом по рамкам; «Настройки Wi-Fi» открывает системный экран Wi-Fi; `svc wifi enable` + «Повторить» → каталог снова «Новые · 615 книг» без перезапуска. `typecheck.sh` — 0 ошибок, `assembleDebug` — BUILD SUCCESSFUL.

## 2026-11-13 — П. 10, шаг 10.12: пароль каталога шифруется (Sonnet)

- **Зачем.** Проверка на книге показала: `catalogs.pass` лежал открытым текстом, и его читал любой, кто воткнул книгу в компьютер — `run-as` для debug-сборки, `adb root` для любой (на прошивке `ro.debuggable=1`, `adb root` работает без разблокировки), плюс `ro.crypto.type=unsupported` — шифрования диска нет. Хешировать нельзя: вход OPDS по HTTP Basic, серверу нужен сам пароль.
- **`core/Pass.kt`.** AES-256/GCM, ключ в `AndroidKeyStore` (алиас `dexpm8.catalog.pass.v1`, `KeyGenParameterSpec`, GCM, 128-битный тег). Хранится строкой `v1:` + Base64(IV ‖ шифртекст): префикс отличает шифртекст от старых открытых паролей. IV — случайный от keystore, поэтому два одинаковых пароля дают разные строки. Ключ один раз читается из keystore и держится в памяти (`@Volatile` + `synchronized`): каталоги сохраняются с фонового потока, без блокировки можно было создать два ключа и потерять первый. Ошибка keystore — `""` и запись в трассу, открытым текстом пароль не пишется никогда.
- **База v7.** `addCatalog`/`catalogAuth` пишут `Pass.seal`, `Catalog.pass` — `Pass.open` (строка без префикса возвращается как есть: это запись от версии 6). Миграция `sealCatalogPasswords` в `onUpgrade` внутри готовой транзакции.
- **Грабли (главные в шаге).** (1) `VACUUM` внутри `onUpgrade` падает: `cannot VACUUM from within a transaction` — `SQLiteOpenHelper` держит транзакцию. Поэтому уборка вынесена в `scrub()` и вызывается из `LibraryDb.open()` сразу после открытия базы (в `EinkActivity` — `LibraryDb(this).also { it.open() }`). (2) **`UPDATE` не стирает старое значение**: после перешифрования открытый пароль ещё находился `grep`-ом по `library.db` (освободившееся место в странице). Помогла только пара `VACUUM` → `PRAGMA wal_checkpoint(TRUNCATE)`; без `VACUUM` пароль остаётся в файле базы, без checkpoint — в `-wal`.
- **Проверено на книге 2026-11-13.** Взяли базу от версии 6 (открытый пароль, `user_version = 6`), поставили APK, запустили: `pass` → `v1:8ttq…`, `user_version = 7`, `grep Citadel1977` по `library.db` и `library.db-wal` → **0**, трасса: «перешифровано 1 паролей каталогов» → «уборка после перешифрования готова». Вход работает: корень — 8 записей, «All Books» — 50 книг, 401 нет (сервер принял расшифрованный пароль). `typecheck.sh` — 0 ошибок, 174 класса; `assembleDebug` — BUILD SUCCESSFUL.
- **Предел, чтобы не обманываться.** Ключ лежит в `/data/misc/keystore` на том же устройстве: с `adb root` его достают вместе с базой. Это заметно сложнее, чем `select pass`, но абсолютной защиты на userdebug-прошивке без шифрования диска нет. `allowBackup=false` и раньше закрывал `adb backup` (файл 0 байт — проверено).

## 2026-11-13 — П. 10, шаг 10.9: поиск в каталоге OPDS (Sonnet)

- **Ядро `core/Opds.kt`.** `rel="search"` бывает двух видов, и это выяснилось на живом BookLore: Calibre кладёт готовый шаблон с `{searchTerms}` прямо в фид, а BookLore — **ссылку на OpenSearch-описание** `application/opensearchdescription+xml` (`/api/v1/opds/search.opds`), где шаблон лежит в `<Url template="/api/v1/opds/catalog?q={searchTerms}">` (проверено по исходникам `booklore-app/booklore`: `OpdsFeedService.getOpenSearchDescription`). Поэтому `searchTemplate(feed, auth)`: адрес с подстановкой — берём как есть; иначе **один раз** дочитываем описание и держим шаблон в памяти (иначе каждая правка запроса — два сетевых запроса). Разбор описания — чистая `parseTemplate(bytes, base)` в `companion object`: JVM-проверка без `Context`; при нескольких `<Url>` предпочитается `kind=acquisition` (в описании бывает и навигационный шаблон).

## 2026-11-13 — П. 10 «Сетевые каталоги OPDS»: ядро, база v6, пять экранов

- **Ядро `core/Opds.kt`.** Свой клиент OPDS 1.x без зависимостей: `HttpURLConnection` + `XmlPullParser` из `android.jar` (на 1 ГБ ОЗУ и API 27 Gradle-библиотеки ради разбора Atom не нужны). Потоковый разбор (не `Document` целиком) + предел `MAX_BYTES = 4 МБ` — фид Calibre на тысячи книг не съест heap. `ETag`/`Last-Modified` и кэш в `cacheDir/opds/<url.hashCode()>`: повторное открытие не ходит в сеть, а без сети отдаёт последний фид. `parse(bytes, base)` вынесен в `companion object` — чистая функция, её проверяют на JVM без `Context`.
- **Загрузка** — по образцу `WifiShare`: пишем в `<имя>.part` и переименовываем только после конца; оборванная загрузка в библиотеку не попадает. Имя из `Content-Disposition`/заголовка записи, с очисткой запрещённых FAT знаков и без перезаписи (`.fb2`, `(2).fb2`).
- **База v6.** Таблица `catalogs` (`url` UNIQUE, `title`, `user`, `pass`, `added`, `seen`). В базе только то, что ввёл человек; фид и `ETag` — в кэше, его можно стереть без потери настроек. `LibraryDb.normalizeUrl` дописывает `http://` и убирает хвостовой `/` — иначе один каталог лежит в базе дважды.
