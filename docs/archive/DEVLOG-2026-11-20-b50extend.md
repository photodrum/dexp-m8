# B50 — расширение выделения касанием по маркеру (2026-11-20, Sonnet)

Подробности к записи DEVLOG от 2026-11-20. Пункт 17 `docs/ROADMAP.md`; ТЗ — `docs/READER_SPEC.md`,
раздел 5 («выделение»). Числа — `design/v5/B50.json`.

## Решение

Вопрос в `docs/DESIGN_QUESTIONS.md` от 2026-11-17 («как расширять выделение») закрыт ответом
пользователя 2026-11-20: **вариант 1 — касание по маркеру расширяет выделение на слово,
повторные касания — дальше**, маркеры остаются на месте макета. Клавиши «‹»/«›» в меню
(потребовали бы новый борд — в макете их нет) и «оставить одно слово» отклонены.

## Что сделано

| Что | Как |
|---|---|
| геометрия маркеров | `ReaderScreen` запоминает `markStartX/Y`, `markEndX/Y` при отрисовке (`drawSelectionOver`), касание считает по ним же — одна геометрия для рисования и касаний (`READER_SPEC`) |
| `markerHit` | попадание с запасом `MARK_HIT_PAD` = 45 по бокам (6 + 90 = 96 дизайн-px — минимум тач-зоны по `ARCHITECTURE.md`), по вертикали 12 (72.4 + 24 = 96.4). Запас урезается половиной зазора между маркерами, чтобы на коротком слове их зоны не слились |
| `extendSelection(dir)` | `Engine.selectionExtend(±1)` → перечитать текст, позиции, отрезки; перед запросом `Engine.syncPage(page)` — иначе фоновая отрисовка соседней страницы уводит движок (грабля 2026-11-17) |
| откат | если расширенное слово ушло за край страницы (`rangeRects` пуст), граница возвращается `selectionExtend(-dir)`: иначе выделение «пропало» бы с экрана, оставшись в движке |
| порядок касаний | клавиши меню → маркеры → «мимо» снимает выделение. Меню проверяется первым: у последних абзацев панель стоит **над** выделением и накрывает маркеры — что нарисовано сверху, то и нажимается |
| зона шторки B5 | `shadeAllowed` уступает касание и по маркерам (`markerHit != MARK_NONE`), а не только по панели |
| сброс | `markShown = false` при снятии выделения и при листании (`show`) — касание по несуществующему маркеру не считается |

## Попутно исправлено

**Маркер конца стоял не там, где в макете.** Было `markEndY = bottom − MARK_OFF_Y − MARK_EXTRA_Y`,
то есть от **низа** всего выделения; в макете же маркер конца — у **последней строки**
(1305,326.2 при строке 330.2…394.6 — на 4 выше её верха). На многострочном выделении маркер
уезжал вверх на высоту строки и наезжал на меню B50. Теперь считается от `lastTop` — верха
последней строки; константа `MARK_EXTRA_Y` убрана.
