## 2026-11-13 — П. 10, шаг 10.11: срезы «Авторы/Серии/Жанры» B64–B69 (Sonnet)

- **Зачем.** Сегменты на B16 переключали вид, но срезы показывались только если каталог отдал их записями в текущем фиде; отдельных экранов B64–B69 не было. Проверено на живом BookLore: он отдаёт `/api/v1/opds/authors` (442 автора) и `/series` (147 серий), **жанров не отдаёт вовсе** (`/genres` → HTML приложения, не OPDS).
- **`core/Opds.kt`.** `Feed.subsections` — ссылки `rel="subsection"` самого фида (BookLore так не делает: срезы у него записями, но у части каталогов — только ссылками). `sliceHref(feed, kind)` (публичный `findSlice` — `opds.findSlice`): срез ищется по адресу записи-навигации (`author`/`series`/`genre|tag|subject`), затем по названию записи («Авторы», «By Author», «Tags»), затем по `subsections` фида. `Opds.Slice` — вид среза; числа совпадают с индексами сегментов, поэтому экран передаёт номер сегмента.
- **Экран.** `tab` — 0 «Новые» (B16), 1…3 — срез. `openSlice(kind)` грузит фид среза в фоне; `inSlice` — открыты книги среза. Список среза: строки 548 + 184·i, шесть строк, разделитель 237,y+147.5 1076×2, панель 1099.1; круг 88,y+4.1 115×120 — инициалы у авторов, `list@38.4x40` у серий, `library@38.4x40` у жанров (126.8,y+39.1). Книги среза — те же строки, что в B16 (5 штук, шаг 214). Шапка: B16/B64 — название каталога из базы (`catTitle`), B65/B67/B69 — имя среза; подзаголовок списка «Авторы · 442» (без слова «книг», как в макете), книг среза — «Авторы · 1 книга».
- **Навигация.** «Назад» в шапке из книг среза возвращает к списку среза (`backToList`) — список, его строки и страница лежат в памяти (`sliceFeed`/`sliceRows`/`slicePage`), запроса к серверу нет. «×» в поиске из среза возвращает к списку среза, из корня — к корневому фиду. Среза нет (жанры BookLore) — карточка B44 «Нет раздела / Каталог не отдал этот раздел», в сеть не идём.
- **Грабли.** (1) **Имя `slice` не компилируется снаружи**: `Opds.slice(feed, kind)` разрешается в стандартное расширение `List.slice<Int>()`, ошибка `unresolved reference` — переименовано в `findSlice` (ловится только сборкой, `typecheck` со старой сигнатурой тоже ругался, но причину видно лишь по тексту `slice(indices: IntRange)`). (2) `private companion object` в `Opds` — константы `Opds.SLICE_*` недоступны экрану; вид среза вынесен в отдельный `object Slice`. (3) С клавиатурой B48 в списке среза пятая строка (1284…1433.5) уходила под лист — при `kbOpen` в срезе четыре строки (`PER_PAGE_SLICE_KB`). (4) У записи-навигации среза своего счётчика книг нет, а `content` у BookLore — «Books by …»; такие подписи не показываем (`sliceSummary`), иначе в строке висел бы повтор названия.

Лема; «Новые» возвращает корень (8 разделов, 1/2); поиск из среза «жн» → «Поиск · 10 книг», «×» → список авторов. `tools/typecheck.sh` — 0 ошибок, 177 классов; `assembleDebug` — BUILD SUCCESSFUL; JVM-харнесс срезов — 19 проверок, «=== ВСЁ ОК» (`docs/BUILD.md`).
