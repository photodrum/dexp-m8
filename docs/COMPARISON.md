# Сравнение вариантов читалки: Book's Story — KOReader — своё ядро

## Как устроены

**Book's Story** (github.com/Acclorite/book-story) — Kotlin + Jetpack Compose, GPL-3.0,
Android 8.0+, форматы FB2/EPUB/PDF/TXT/HTML/MD.

**KOReader** (github.com/koreader/koreader) — Lua + C, AGPL, Android 4.3+. Лучший движок
для E-Ink: свой рендеринг, постраничная вёрстка, оптимизация под медленные экраны.
Интерфейс на Lua в собственной системе виджетов.

**Своё ядро на C** — то, что делается в этом проекте: разбор FB2/EPUB на C99,
вёрстка постранично, отрисовка через наш `Canvas`.

## Сводная таблица

| | Book's Story | KOReader | Своё ядро |
|---|---|---|---|
| Язык UI | Kotlin + Compose | Lua | Kotlin, без AndroidX |
| Рендеринг | Compose | свой (C/Lua) | свой (`Canvas`) |
| PSS на PX30 | ~90–140 МБ | ~50–70 МБ | ~25–35 МБ (цель) |
| Скорость листания | jank на перерисовке | быстрая | зависит от вёрстки |
| FB2 | через парсер | отличный | свой парсер |
| EPUB | да | отлично | нужно дописать (zlib) |
| Совпадение с макетом | перекраска, ~80 % | приблизительно, патчи | 100 % |
| Лицензия | GPL-3.0 | AGPL | GPL-2.0-only (с 2026-11-11; до этого AGPL-3.0) |
| Трудозатраты | низкие | низкие (настройка) | высокие |

## Что у кого лучше / хуже

**Book's Story.** Плюс: почти всё готово, форматы есть. Минус: Compose на PX30 с 1 ГБ —
это и память, и jank при полной перерисовке; под E-Ink его никто не оптимизировал.
Перекраска под макет возможна, но анимации Compose придётся выпиливать по одной.

**KOReader.** Плюс: эталон работы с E-Ink, FB2 идеальный. Минус: интерфейс на Lua,
макет B3/B4 повторить точно нельзя — только приблизительно через настройки и патчи.
AGPL означает, что наши правки тоже должны быть открыты.

**Своё ядро.** Плюс: полный контроль, 100 % совпадение с макетом, минимум памяти.
Минус: писать и отлаживать вёрстку самому — самая долгая часть проекта.

## Решение от 2026-11-07 (пересмотрено 2026-11-08, см. ниже)

Оболочка (лаунчер, библиотека, настройки, плеер) — своя, на Kotlin без AndroidX.
Читалка — своё ядро на C99 через JNI. Причина: экран 1404×1872 E-Ink и требование
100 % совпадения с макетом несовместимы с чужим UI, а по памяти на 1 ГБ выигрыш
у собственного `Canvas`-рендера решающий.

Запасные варианты, если своё ядро застрянет: KOReader как читалка «снаружи» (запуск
через Intent), CoolReader NG / LxReader для FB2.

## Пересмотр решения (2026-11-08)

**Читалка = свой UI + готовые движки.** Страницу рисуют CREngine (FB2, EPUB, MOBI, TXT,
RTF, DOC), MuPDF (PDF, CBZ) и DjVuLibre (DjVu); всё вокруг страницы — наш `Canvas`
по макету, поэтому совпадение с макетом остаётся 100 %. Своя вёрстка на C снята.

Почему: своя вёрстка — это переносы, сноски, таблицы, CSS из EPUB, кодировки, MOBI/RTF/DOC;
месяцы работы с результатом хуже готового движка. CREngine — тот же движок, что внутри
KOReader и CoolReader, проверен на E-Ink.

Что остаётся от «своего ядра»: `book.c` — быстрый разбор метаданных FB2 для сканера
библиотеки. Лицензия проекта — GPL-2.0-only (CREngine — GPL-2.0, MuPDF с ним несовместим и убран).

Риск — память и скорость на PX30. Его снимает проба R0 до начала работы над читалкой.
Если R0 не пройдёт, запасной путь прежний: KOReader через Intent. Подробно —
`docs/READER_SPEC.md`.
